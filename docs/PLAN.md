## 完成定义

世界从 Wilson 已向 Holmes 讲完红发会解散、当晚行动尚未发生的时刻开始。玩家在 Luanti 中能够：

1. 在贝克街、当铺、地窖和相邻银行之间行动，并实际进入、观察场景中的故事对象。
2. 发现线索并在可查看的调查记录中看到其来源、发现地点和当前解释；未知或推断不得伪装成事实。
3. 向至少一名角色发起交流，看到对方有来源可追溯的回应；玩家输入与角色亲历分开记账，角色只知道其听到或观察到的内容。
4. 继续观看至少数个世界决策步：角色依据自己的目标和知情采取行动，至少一项行动改变可检查的世界状态，并能看到相应事件或资源后果。
5. 正常停止并恢复同一世界后，线索、角色记忆、消息和后果仍一致，不重复结算。

不能用预写的结局、强制台词或注入行动满足“世界自主继续”。证据须明确标记是真实模型、确定性产品规则还是验证夹具。最终结局可以不同于原作。真人在 Luanti 中实际完成“调查—交谈或干预—观察后果—恢复继续”的游玩，是本里程碑最后一项验收。

## 严格执行顺序

阶段依赖是顺序门槛：先确定交互和数据归属，再接入线索及场景，然后让角色在该状态上继续演化，最后验证恢复和真人玩法。某阶段未达验收条件，不把它标为完成，也不把后续阶段的夹具结果算作产品证据。

### 3. 角色自主延续和可见后果

- [x] 玩家输入进入目标角色的 `direct.messages`，故事物件只在角色有权且物理范围足够近时进入当前观察；provider 输出只允许回应一条已提供私信或提交一项已提供的物件转换。Luanti 执行器再次检查范围、授权、修订号和对象绑定。
- [x] v7 四名角色各完成一次真实模型决策；v10 和 v11 均有四名角色的多轮真实模型动作，并出现 NPC 消息、角色移动和地窖工作面状态事件。模型提出行动，产品执行器按授权与状态规则落地；尚未证明条件变化会稳定引出不同后续计划。
- [x] 本地确定性 Lua/Python 测试夹具覆盖隐私、过期动作、距离、世界节点投影和物件变化；它只证明集成契约，不证明模型质量。
- [x] 用户已授权调用所选 provider。运行记录注明 SCNet / GLM-5.3-Flash、每轮间隔、单 worker、请求字段范围、有效动作和失败；v7 私有模型审计留在本地世界目录，v10 与 v11 未启用输入／输出审计。
- **验收：** 有至少一条跨多个决策的可复核轨迹：观察或玩家消息 → 角色决定 → 执行器结果 → 世界状态／事件 → 可见后果；至少一个条件变化产生与旧预测不同的新决策。轨迹中未发生的原作情节不得预先注入。

- [ ] v11 进程已退出但 recovery marker 仍在，日志没有正常 checkpoint 完成记录。退出原因与最后一致提交状态待核对；恢复前不得删除标记或直接拼接不同版本的状态。
- [ ] 尚未从当前可玩世界通过玩家调查／私信产生后果，再正常停止并恢复同一世界核对节点、日志、记忆和对话。v10 有模型后果但未能恢复，不计作通过。

- **验收：** 从已产生后果的检查点停止后恢复，身份、对象、事件、消息和记忆一致；故障注入无丢失、重复结算或越权知情。当前多存储并非原子事务的限制必须保持明确。

### 5. 本机试玩与里程碑验收

- [x] 从干净起点 v11 曾首次启动产品世界并由本机 Luanti 客户端连接；出生点、开放问题、移动／调查／交谈提示及故事对象入口随当次代码加载。真实 provider 当时以 60 秒间隔、单 worker 运行；当前相关进程均已退出。
- [ ] 提示可读、调查与私聊入口可用仍待客户端验证；当前没有可核验的真人调查／私信结果。尚未为核验导出玩家私有消息正文。
- [ ] 保留完整验收证据：起点版本、配置的认知模式、玩家交互、角色可见输入、决策与失败、状态差异、恢复结果及使用范围。
- [ ] 完成客户端交互、真实模型对玩家输入的回应、后果与恢复验证后，再记录真人体验和剩余问题。当前既有开发／端到端验证待办，也有真人验收待办；自动化截图、fixture 或模型互评不能替代真人游玩。
- **验收：** 玩家无需开发者解释即可找到一个有意义的行动；至少观察到一项不是环境装饰的故事变化，并在恢复后继续。通过前保持本阶段未完成。

## 验证与资源边界

- 先跑与改动对应的本机定向检查；不因单元测试通过就宣称端到端完成。运行 Luanti 客户端前检查 `MemAvailable`、内存 PSI 和 `/tmp`；保留现有桌面与用户进程。
- 较重构建、全量测试和 GUI 自动化按仓库约定优先迁到免费 CI。真实 provider 调用使用用户已授权的 SCNet 配置；请求会包含角色身份与目标、私有起始记忆、当前观察和允许动作，玩家发起私信时还会包含该条私信。新云端运行、代码上传或超出上述模型输入范围的外发仍需单独确认。
- 运行证据必须保留分支提交／快照、产品配置、真实模型与确定性规则边界、失败和资源用量。不得把真实模型决策伪装成夹具，也不得把规则实体容量写成真实 LLM 角色容量。
- 运行前与结束后都更新本文件的阶段状态和[文档索引](README.md)；不另建相互竞争的实施计划。

## 《红发会》之后的 Wispiva 工作

这些方向不阻挡当前可玩世界里程碑，但在各自被实现和验收前仍是产品待办：任意用户意图到可确认世界的泛化、任意区域／房型／出入口生成、跨组件原子提交与崩溃回滚、长程记忆事实性和语义检索、可调持续时间与长期无人观看运行、不同题材的端到端创建、规模与真实模型服务容量、多线分岔和并行世界比较。既有测量与限制见[计划审计](design/2026-10-30-plan-audit.md)、[容量证据](../evidence/luanti/agent/capacity-2026-10-30.md)、[自由社会证据](../evidence/luanti/product-model-2026-10-30/README.md)。
