## 完成定义

世界从 Wilson 已向 Holmes 讲完红发会解散、当晚行动尚未发生的时刻开始。玩家在 Luanti 中能够：

1. 在贝克街、当铺、地窖和相邻银行之间行动，并实际进入、观察场景中的故事对象。
2. 发现线索并在可查看的调查记录中看到其来源、发现地点和当前解释；未知或推断不得伪装成事实。
3. 向至少一名角色发起交流，看到对方有来源可追溯的回应；玩家输入与角色亲历分开记账，角色只知道其听到或观察到的内容。
4. 继续观看至少数个世界决策步：角色依据自己的目标和知情采取行动，至少一项行动改变可检查的世界状态，并能看到相应事件或资源后果。
5. 正常停止并恢复同一世界后，线索、角色记忆、消息和后果仍一致，不重复结算。

不能用预写的结局、强制台词或注入行动满足“世界自主继续”。证据须明确标记是真实模型、确定性产品规则还是验证夹具。最终结局可以不同于原作。真人在 Luanti 中实际完成“调查—交谈或干预—观察后果—恢复继续”的游玩，是本里程碑最后一项验收。

## 严格执行顺序

阶段依赖是顺序门槛：先确定交互和数据归属，再接入线索及场景，然后让角色在该状态上继续演化，最后验证恢复和真人玩法。某阶段未达验收条件，不把它标为完成，也不把后续阶段的夹具结果算作产品证据。

## 验证与资源边界

- 先跑与改动对应的本机定向检查；不因单元测试通过就宣称端到端完成。运行 Luanti 客户端前检查 `MemAvailable`、内存 PSI 和 `/tmp`；保留现有桌面与用户进程。
- 较重构建、全量测试和 GUI 自动化按仓库约定优先迁到免费 CI。真实 provider 调用使用用户已授权的 SCNet 配置；请求会包含角色身份与目标、私有起始记忆、当前观察和允许动作，玩家发起私信时还会包含该条私信。新云端运行、代码上传或超出上述模型输入范围的外发仍需单独确认。
- 运行证据必须保留分支提交／快照、产品配置、真实模型与确定性规则边界、失败和资源用量。不得把真实模型决策伪装成夹具，也不得把规则实体容量写成真实 LLM 角色容量。
- 运行前与结束后都更新本文件的阶段状态和[文档索引](README.md)；不另建相互竞争的实施计划。

## 《红发会》之后的 Wispiva 工作

这些方向不阻挡当前可玩世界里程碑，但在各自被实现和验收前仍是产品待办：任意用户意图到可确认世界的泛化、任意区域／房型／出入口生成、跨组件原子提交与崩溃回滚、长程记忆事实性和语义检索、可调持续时间与长期无人观看运行、不同题材的端到端创建、规模与真实模型服务容量、多线分岔和并行世界比较。既有测量与限制见[计划审计](design/2026-10-30-plan-audit.md)、[容量证据](../evidence/luanti/agent/capacity-2026-10-30.md)、[自由社会证据](../evidence/luanti/product-model-2026-10-30/README.md)。
