## 本轮目标与状态

目标仍是一条完整体验：用自然语言创建湖边木屋和修表老人，检查可进入的空间，局部修改窗户及屋顶，保留其余内容；撤销、刷新和重启后可恢复；确认进入后观察至少一次人物行动。木屋只是验收样例，不是固定产品模板。

**反馈、恢复、保存、空间检查、等待进度、短步骤约束和“自动建造并检查” loop 已实施。loop 最多运行 4 轮，应用内所有模型请求默认限时 180 秒。每轮读取最新体素版本和诊断，只提交增量修改，进程重启后会把已提交轮次恢复为部分完成。完整单层建筑可由模型提供一个结构方案，再由程序编译成有边界检查的地板、墙、两格门洞、门外支撑地面、坡屋顶和对象登记；空场景简单单层房屋必须只输出一个结构方案。loop 会优先执行已有的精确门洞／窗户修复，并只在轮数预算内重试 JSON／讨论格式或命令校验错误；网络失败、超时、取消和过期基准会立即停止。起点校验失败时界面最多显示三条诊断消息和路径，不显示内部 detail。真实模型曾生成 121 格和 159 格、零空间诊断的木屋，也曾完整完成一次建造后补地板缺口；独立复验又出现格式错误和空响应，重复性仍未通过。2026-11-04 三次隔离海岸起点生成分别遇到隐私审计拒绝、空正文和超时，均未进入居民行动验证。早先湖边木屋 loop 提交 347 格、3 个对象但留下 5 项空间问题，继续修复后无进展；简化单轮曾提交 39 格但留下 2 项问题。云端浏览器已目视检查 532 格合成湖岸场景、室内石桌、角色地点投影和遮挡后的全景／室内截图；真实模型生成同场景视觉仍缺证据。**

## 尚未通过项与下一顺序

## 本轮执行计划

以下计划把“待办”拆成可独立验证的工作流。代码、确定性测试和验收工具可以在本机完成；真实模型行为、真实画面和长期运行必须保留真实证据，不能用合成模型测试替代。

### A. 自动建造 loop 稳定性

- [x] 保持每轮读取最新 `voxel.revision`、方块、对象和空间诊断，只提交增量修改。
- [x] 增加最多轮数、180 秒单请求超时、无进展、取消、过期基准和“前几轮已提交但后续失败／重启”的回归覆盖。
- [x] 明确最终状态：全部诊断清零为完成；达到轮数仍有诊断为部分完成；无进展、超时或请求失败保留意图和当前诊断，前序已提交修改继续可用。
- [x] 修正空场景误报：自动建造在零方块场景收到空命令时，即使空间诊断为零也返回未建造，不再报告完成。
- [x] 修正对象引用提示：若写入命令带 `objectId`，同一批命令必须含同 ID 的 `op:"object"` 注册，且对象范围需覆盖写入范围；新增定向回归。
- [x] 根据真实诊断补足建筑约束：整栋房屋只登记一个完整 `building` 对象，局部门洞不单独登记为建筑；门洞固定两格高并保留墙顶；不支持的建筑范围明确返回跨度与分类建议。
