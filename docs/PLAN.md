更新日期：2026-11-03。本分支只做原型。[产品意图](intent.md)说明目标，[架构](architecture.md)说明当前实现，[体验记录](notes/2026-10-29-creation-experience.md)保存 10 月 29 日的真实观察。

## 本轮目标与状态

目标仍是一条完整体验：用自然语言创建湖边木屋和修表老人，检查可进入的空间，局部修改窗户及屋顶，保留其余内容；撤销、刷新和重启后可恢复；确认进入后观察至少一次人物行动。木屋只是验收样例，不是固定产品模板。

**反馈、恢复、保存、空间检查、等待进度、短步骤约束和“自动建造并检查” loop 已实施。loop 最多运行 4 轮，每次模型请求有 180 秒上限；每轮读取最新体素版本和诊断，只提交增量修改，进程重启后会把已提交轮次恢复为部分完成。确定性回归覆盖完成、轮数上限、无进展、过期版本、超时、取消、请求失败和重启恢复。真实模型三次隔离复验均未完成完整建造回路，出现空正文、长时间无响应和格式无效；模型稳定性未通过。既有真实体验曾完成分步木屋建造与空间修复，主流程也走通过人物行动。最近一次实际浏览器验收确认有内容时画面能正常显示，并修复了异步载入期间的空白状态与无效行动后的按钮误导；视觉质量仍未达到整体验收标准。**

## 验证证据

GitHub Actions 的既有验证记录（运行 `40999695061`）在独立验证分支执行了完整离线检查、创建／运行浏览器流程、体素浏览器流程及失败恢复流程，使用合成模型；该记录包含 **135 个 Node 测试、282/282 项环境检查、40/40 条模型客户端观察**，并通过所有浏览器流程。体素报告还确认精确部件换色、室内查看、刷新／重启和确认进入保持同一场景快照。该验证不读取私有模型配置或存档，不能替代当前工作树的本机检查。

2026-11-03 本机运行 `npm run check`：**149 个 Node 测试、282/282 项环境检查、41/41 条模型客户端观察、33/33 项 UI 观察和 28/28 项创建服务观察全部通过**；此检查使用合成模型，没有发起真实模型请求或启动浏览器。测试包含第二轮读取首轮提交后的体素版本和诊断、轮数上限、无进展、过期基准、超时、取消、后续网络失败和进程重启后的部分完成恢复、平地／水面人物投影，以及地点级人物状态。创建服务观察覆盖地点状态模块的 JavaScript 静态投递；回归先复现 `404`，加白名单路由后通过。完整检查输出保存在本轮 `.audit/plan-closeout-full-check.log`，静态路由红／绿证据保存在 `.audit/plan-closeout-static-route-red.log` 和 `.audit/plan-closeout-static-route-green.log`。

同日运行 `npm run benchmark:voxel`：756 格样本上下文 2,918 字节、快照文件 30,882 字节、重载后 756 格，总耗时约 5.9 ms；5,000 格样本上下文 7,442 字节、快照文件 206,088 字节、重载后 5,000 格，总耗时约 12.0 ms。总耗时包含样本写入、上下文生成和重载，不是纯磁盘加载时间；基准不测浏览器或 GPU 渲染性能。

合成体素样本已测到 5,000 格，但这只验证上下文、快照大小和重载后的数据完整性；真实大场景编辑、浏览器／GPU 帧率、内存曲线和长期存档增长仍未验证。既有 requestAnimationFrame 回调不是 GPU 帧率。具体环境、耗时与失败见体验记录，不在多份文档重复维护。

## 尚未通过项与下一顺序

1. **真实模型修复稳定性。** 入口已经一次只携带一个 issue，并传对象 ID、问题代码、具体坐标和对象归属边界；入口和窗户归属已有确定性直接修复，模型路径新增提示后一次真实修复成功，但此前仍出现截断、网络错误和 144 秒长等待。下一步要继续测量供应商响应稳定性，并把更多安全的检查项纳入直接修复。
2. **视觉质量复验。** 2026-10-29 的一张浏览器观察曾显示 758 格场景中的湖水、木屋和人物；这只是当时一个状态。本轮将同一真实模型生成的存档推进到第 1440 分钟后，角色当前位置为 `lake`，对应对象范围内 77 格全是水，没有可站立支撑，因此人物实体不显示。画布下方现在会明确显示地点级状态，不会伪造其精确位置。屋顶、墙体和家具仍像粗糙体素块，湖岸、水面、家具和多角度画面尚未完成验收。
3. **持续行为。** 主流程曾完成确认、人物行动与修理进度变化。本轮真实生成场景的一天回放验证了历史、记忆及存档重载，但第 13 分钟之后没有新的行动；最近 120 条历史中没有动态事件，角色位于全水地点时也没有投影。一次新模型行动请求返回 `network-error`。仍需在行为有变化且角色位置能正确显示的真实场景上复验；大场景性能另行测量。

## 本轮执行计划

以下计划把“待办”拆成可独立验证的工作流。代码、确定性测试和验收工具可以在本机完成；真实模型行为、真实画面和长期运行必须保留真实证据，不能用合成模型测试替代。

### A. 自动建造 loop 稳定性

- [x] 保持每轮读取最新 `voxel.revision`、方块、对象和空间诊断，只提交增量修改。
- [x] 增加最多轮数、180 秒单请求超时、无进展、取消、过期基准和“前几轮已提交但后续失败／重启”的回归覆盖。
- [x] 明确最终状态：全部诊断清零为完成；达到轮数仍有诊断为部分完成；无进展、超时或请求失败保留意图和当前诊断，前序已提交修改继续可用。
- [x] 在同一隔离提示上完成三次真实模型复验并检查调用记录：第一次 13.4 秒返回空正文；第二次首轮 151.6 秒提交 815 格但仍有 3 项空间问题，后续修复调用超过 5 分钟未返回并被停止，重启恢复为部分完成；第三次 25.7 秒返回无效建造回复，没有提交。三次都没有完成整条回路。
- [x] 做两次不含世界数据的限额连通性探测：Responses 端点均返回 HTTP 200，但 16／128 输出 token 上限下没有正文；128-token 请求以 `incomplete/max_output_tokens` 结束。该人工限额探测只能证明请求到达服务端，不能证明实际建造提示可成功，也不算完整回路。
- [ ] 在真实模型上完成重复的完整建造与修复回路；上述实测表明当前稳定性尚未通过，不能以本地超时回归替代。

完成判据：确定性状态覆盖及 `npm run check` 已通过。真实模型稳定性实测未通过，须修复空正文、无效回复及长延迟问题后再做完整回路验收。

### B. 视觉质量

- [ ] 只根据实际画面调整镜头、材质、阴影和体素表现，避免用空间诊断代替审美验收。
- [ ] 补充一个低负载的场景边界／渲染回归，确保画面调整不改变权威体素状态。

完成判据：有可复查的浏览器画面或等价观察记录；小场景主要结构清楚，多角度和室内查看没有明显遮挡或空白。云端或本机 GUI 验收的权限、资源和运行条件必须单独记录。

### C. 持续行为

- [x] 增加一天级别的确定性行为回归：至少包含行动成功、行动失败、资源变化、疲劳变化、暂停／恢复和存档重载。
- [x] 对真实模型创建的存档做一天级确定性推进：原存档在第 13 分钟且没有持续过程；调用审计有 41 条早先的模型请求，均为 `spark-x2.6`，不代表回放期间有模型行为。从第 13 分钟推进 1,427 分钟至第 1,440 分钟后，保存重载的 revision 为 1453、history 有 1454 条且最新历史与当前世界一致，13 条既有记忆保留。

完成判据：确定性回归覆盖完整轨迹；真实场景有完整一天观察记录，且能核对行为动态、角色地点投影、记忆和存档重载。当前存档／记忆一致性通过，动态及湖面地点的角色显示未通过。长期记忆、反思和分岔仍属于产品后续范围。
